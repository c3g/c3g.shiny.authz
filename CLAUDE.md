# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

`c3g.shiny.authz` is the R package Shiny apps use for authentication/authorization UI concerns
when running behind oauth2-proxy on C3G's shared webapp VM -- see
[web-app-template](https://github.com/c3g/web-app-template)'s `for-app-developers.md`
(`#real-tier-3-for-shiny`) for where this sits among the tiers. Dotted package name, not
hyphenated -- R's naming convention, unlike the Python packages in this stack (`c3g-oidc`,
`c3g-flask-opa`).

Two exported functions, in `R/groups.R` and `R/authz.R`:

- `c3g_groups(session)` -- Tier 2, cosmetic. Parses `X-Forwarded-Groups` from
  `session$request`. Not a security boundary: oauth2-proxy already made the actual access
  decision before Shiny saw the request. Real, working implementation.
- `c3g_require_authz(action, session, policy_path, opa_url, timeout)` -- Tier 3, real
  authorization. Calls the app's local OPA sidecar at `v1/data/<policy_path>` with
  `{action, groups}`, fails closed on any error reaching it (including the 2-second timeout and
  an undefined rule). Verified against a real OPA server and in a running app -- see "What's
  actually verified" below.

No OIDC-client layer is planned here -- oauth2-proxy stays in front regardless of tier, since
Shiny has no non-browser client the way `pt_cli` justifies `c3g-oidc` for `project_tracking`.

## Design notes

- **Fail closed.** `c3g_require_authz()` treats any error reaching OPA (network failure,
  non-2xx response, malformed body) as a deny, never as an allow. Don't "helpfully" change the
  `tryCatch` in `authz.R` to retry-then-allow or to log-and-continue -- an OPA outage should
  block the action, not silently open it up.
- **No path/method in the OPA input, unlike the Flask side (`c3g-flask-opa`).** Shiny apps are
  single-page, so there's nothing route-shaped to key a decision off -- `c3g_require_authz()`
  sends `{action, groups}` only. Keep the input shape minimal; don't add fields "for
  consistency" with the Flask input shape unless a real Shiny app's policy actually needs them.
- **`c3g_groups()` must stay side-effect-free and dependency-light.** It's called from ordinary
  render/UI code, potentially on every reactive tick -- it should never itself call OPA or do
  network I/O. That's what makes it safe to say "not a security boundary, just cosmetic": it
  genuinely can't deny anything.

## What's actually verified

- `c3g_groups()`: unit tested (header present/absent/empty) in `tests/testthat/test-groups.R`.
- `c3g_require_authz()`, in `tests/testthat/test-authz.R`: a missing `policy_path` is a loud
  error; unreachable and hung OPA both deny (the hung case within the timeout); and against a
  real `opa run --server` loaded with `fixtures/example_app/`: allow, deny, no groups, unknown
  action, undefined rule. The real-OPA tests skip without `opa` on a dev machine, and fail
  instead of skipping in CI.
- In a running app, `tests/e2e/shiny-browser.R`: real Shiny + real OPA + headless Chrome,
  through `groups_proxy.py`. Checks the header reaches the app, Tier 2 UI, allowed and denied
  actions (notification shown, handler stopped), no groups, and OPA down (denied, app still
  responsive). Not in CI; run it by hand after changing `authz.R` or `groups.R`.

**This repo is public; `c3g-opa-policies` is private.** Never copy a real app's policy or real
COmanage group names into tests, fixtures, examples or docs -- use the generic `example-*`
groups.

## Releasing

`remotes::install_github("c3g/c3g.shiny.authz@vX.Y.Z")` installs from a tag, so a release is:
bump `Version:` in DESCRIPTION in a PR, merge it, then
`gh release create vX.Y.Z --generate-notes`. The tag must be `v` + the DESCRIPTION version.

CI (`.github/workflows/R-CMD-check.yml`) runs `R CMD check` (without `--as-cran`; this
package isn't headed for CRAN) and fails on any warning. Commit the regenerated `man/` after
`devtools::document()`, or the check warns about undocumented exports.
